
# Auto Report Draft System – Spring Boot 구현 로드맵 (V3 기반)

목표:
V3 설계 문서를 기반으로 **자동 보고서 초안 생성 시스템**을 Spring Boot 프로젝트에 단계적으로 구현한다.
각 단계는 **구현 → 테스트 → 다음 단계** 방식으로 진행한다.

핵심 원칙
- 작은 단위로 구현
- 각 단계마다 테스트 수행
- 변경 이벤트(Change Event) 중심 설계 유지
- 보안 정책 준수 (민감 정보 저장 금지)

---

# 전체 구현 단계 개요

1. ✅ 프로젝트 기본 구조 생성
2. ✅ Project / Repository Mapping 구현
3. ✅ Analysis Request 시스템 + Git Analyzer 구현
4. DB Schema Analyzer 구현
5. API Analyzer 구현
6. Evidence 저장 구조 구현
7. Noise Filtering 구현

12. LLM 요약 모듈 (선택)

# 1단계: 프로젝트 기본 구조 생성 ✅

목표:
Spring Boot 프로젝트 기본 구조를 만들고 핵심 패키지를 생성한다.

베이스 패키지: `io.github.gloryoutput.docsgenerator`

패키지 구조

```
io.github.gloryoutput.docsgenerator
├─ analyzer/
│  ├─ git/          # Git diff 분석
│  ├─ api/
│  ├─ database/
│  ├─ dependency/
│  └─ runtime/
├─ common/          # BaseEntity 등 공통
├─ config/          # 설정 (H2Console, WebConfig, EnvFileLoader)
├─ controller/      # REST Controller
├─ domain/
│  ├─ analysis/     # 분석 요청
│  ├─ project/      # 프로젝트, 프로젝트 코드
│  ├─ repositorymap/ # 레포 매핑, 인증 정보
│  ├─ evidence/
│  ├─ changeevent/
│  ├─ report/
│  └─ ruleset/
├─ dto/
│  ├─ request/
│  └─ response/
├─ enums/
├─ exception/       # GlobalExceptionHandler
├─ service/
└─ util/            # EncryptionUtil
```

필요 의존성

- spring-boot-starter-webmvc (Spring Boot 4.0.3)
- spring-boot-starter-data-jpa
- springdoc-openapi-starter-webmvc-ui
- lombok
- mysql-connector-j
- h2 (개발용)
- jgit
- poi-ooxml

엔티티 기본 공통 필드 (BaseEntity)

- createdAt
- updatedAt
- isDeleted
- deletedAt

DB 컨벤션

- PK: `id_테이블명`, binary(16) (UUID)
- FK: `id_참조테이블명`, binary(16)

환경 설정

- dev 프로필: H2 인메모리, ddl-auto: create-drop
- local 프로필: MySQL 127.0.0.1:3307/reportdb, ddl-auto: update
- prod 프로필: MySQL, 환경변수 사용, ddl-auto: validate
- 환경별 `.env` 파일: `deploy/.env.dev`, `deploy/.env.local`, `deploy/.env.prod`

# 2단계: Project / Repository Mapping 구현 ✅

목표:
하나의 프로젝트가 여러 repository를 가지는 구조 지원

테이블: project_code

| 컬럼 | 타입 | 설명 |
|------|------|------|
| id_project_code | binary(16), PK | 프로젝트 코드 ID |
| project_code | varchar, unique | 프로젝트 코드 값 |

테이블: project

| 컬럼 | 타입 | 설명 |
|------|------|------|
| id_project | binary(16), PK | 프로젝트 ID |
| id_project_code | binary(16), FK | 프로젝트 코드 참조 |
| project_name | varchar | 프로젝트명 |
| active | bit | 활성 여부 |

테이블: project_repository_map

| 컬럼 | 타입 | 설명 |
|------|------|------|
| id_project_repository_map | binary(16), PK | 레포 매핑 ID |
| id_project | binary(16), FK | 프로젝트 참조 |
| repository_name | varchar | 레포지토리 이름 |
| repository_url | varchar | 레포지토리 URL |
| target_branch | varchar | 분석 대상 브랜치 |
| priority_order | int | 우선순위 |
| active | bit | 활성 여부 |

테이블: repository_credential

| 컬럼 | 타입 | 설명 |
|------|------|------|
| id_repository_credential | binary(16), PK | 인증 정보 ID |
| id_project_repository_map | binary(16), FK, unique | 레포 매핑 참조 |
| auth_type | varchar(30) | 인증 방식 (PERSONAL_ACCESS_TOKEN, BASIC_AUTH, SSH_KEY) |
| username | varchar | 사용자명 (선택) |
| encrypted_token | TEXT | AES-GCM 암호화된 토큰 |
| encrypted_password | TEXT | AES-GCM 암호화된 비밀번호 |
| encrypted_ssh_key | TEXT | AES-GCM 암호화된 SSH 키 |

API 엔드포인트

| Method | URL | 설명 |
|--------|-----|------|
| POST | /api/projects | 프로젝트 생성 |
| GET | /api/projects | 프로젝트 목록 조회 |
| POST | /api/projects/{idProject}/repositories | 레포지토리 등록 (벌크) |
| GET | /api/projects/{idProject}/repositories | 레포지토리 목록 조회 |
| PUT | /api/projects/repositories/{idProjectRepositoryMap} | 레포지토리 수정 |
| PUT | /api/repositories/{idProjectRepositoryMap}/credentials | 인증 정보 설정 |
| GET | /api/repositories/{idProjectRepositoryMap}/credentials | 인증 정보 조회 (마스킹) |
| DELETE | /api/repositories/{idProjectRepositoryMap}/credentials | 인증 정보 삭제 (논리) |

구현 파일

# 3단계: Analysis Request + Git Analyzer 구현 ✅

목표:
project_code와 기간을 전달하여 등록된 모든 레포지토리의 Git 변경 데이터를 수집

테이블: analysis_request

| 컬럼 | 타입 | 설명 |
|------|------|------|
| id_analysis_request | binary(16), PK | 분석 요청 ID |
| id_project | binary(16), FK | 프로젝트 참조 |
| requested_by | varchar | 요청자 (선택) |
| start_date | date | 분석 시작일 |
| end_date | date | 분석 종료일 |
| status | varchar(20) | 상태 (PENDING → RUNNING → COMPLETED/FAILED) |
| started_at | datetime | 분석 시작 시각 |
| completed_at | datetime | 분석 완료 시각 |

API 엔드포인트

| Method | URL | 설명 |
|--------|-----|------|
| POST | /api/analysis | 분석 요청 (project_code + 기간) |

요청 예시

```json
{
  "projectCode": "FOOTBALL",
  "startDate": "2024-01-01",
  "endDate": "2026-03-10",
  "requestedBy": "test"
}
```

응답 구조

```json
{
  "success": true,
  "data": {
    "idAnalysisRequest": "...",
    "projectCode": "FOOTBALL",
    "startDate": "2024-01-01",
    "endDate": "2026-03-10",
    "status": "COMPLETED",
    "repositoryResults": [
      {
        "repositoryName": "football_web",
        "totalCommits": 5,
        "commits": [
          { "commitHash": "...", "authorName": "...", "message": "...", "dateTime": "..." }
        ],
        "fileChanges": [
          { "changeType": "MODIFY", "filePath": "src/..." }
        ],
        "error": null
      }
    ]
  }
}
```

Git Analyzer 동작

- JGit으로 레포지토리 클론
- target_branch 기준으로 체크아웃
- 기간 내 커밋 필터링 (CommitTimeRevFilter)
- 각 커밋의 diff 추출 (파일 변경 목록)
- 인증 정보 등록 시 자동으로 토큰 복호화하여 사용
- 분석 실패 시 해당 레포만 에러 표시, 나머지는 계속 진행

구현 파일

- `AnalysisRequest.java`, `AnalysisRequestRepository.java`
- `GitAnalyzerService.java`, `GitDiffResult.java`
- `AnalysisService.java`
- `AnalysisController.java`
- `AnalysisCreateRequest.java`, `AnalysisResponse.java`
